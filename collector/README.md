# 菜单统计 · 第 0 期

只记三个事件，用来验证链路和量级：

| 事件 | 什么时候发 | 带什么 |
|---|---|---|
| `open` | 菜单渲染完 | 初始语言（`es` / `en` / `zh`） |
| `lang` | 客人点了语言按钮 | 切到哪个语言 |
| `staff` | 客人点了「给服务员看」 | — |

`staff` 是目前最接近「成单」的信号。它不等于成单：客人可能看完改主意，服务员也可能录成别的。真实销量在店里那套 POS 里，这边拿不到。

## 收了什么、没收什么

**收：** 会话 id（随机生成，只存在那台手机的内存里，页面一关就没了）、事件名、初始语言、屏幕宽度（按 60px 分桶）、国家代码、服务端收到的时间。

**不收：** IP（Worker 能看到，代码里明确不写入库）、精确位置、User-Agent、任何自由文本、任何能认出是谁的东西。

**不写 cookie，也不写 localStorage。** 所以不需要 cookie 横幅。菜单本身用 localStorage 存客人的清单和语言偏好，那是客人主动要求的功能，和统计是两回事，统计这部分一个字节都不往设备上写。

浏览器开了 Do Not Track 或 Global Privacy Control 的，直接不上报。

**保留期：** 原始事件建议留 60–90 天，之后只留按天聚合的结果。还没写自动清理，第 1 期再加。

## 部署（只需要做一次）

需要一个 Cloudflare 账号（免费，不用绑卡）。下面的命令在 `collector/` 目录里跑。

登录：

```bash
npx wrangler login
```

建数据库：

```bash
npx wrangler d1 create sibisi
```

把它打印出来的 `database_id` 填进 `wrangler.toml`，然后建表：

```bash
npx wrangler d1 execute sibisi --remote --file=./schema.sql
```

设一个读报表用的口令（随便一串长的，记下来）：

```bash
npx wrangler secret put TOKEN
```

部署：

```bash
npx wrangler deploy
```

部署完会打印一个地址，形如 `https://sibisi-stats.<你的账号>.workers.dev`。
把 **`<那个地址>/c`** 填进 `source/data.py` 的 `STATS`，然后 `python3 source/build.py` 并提交。

`STATS` 留空时菜单一个请求都不会发，所以没部署之前推上线也是安全的。

## 看数据

```bash
curl "https://sibisi-stats.<你的账号>.workers.dev/s?k=<你的TOKEN>&d=14"
```

`d` 是往前看多少天（1–90）。返回：总会话数、走到「给服务员看」的比例、按天拆分、初始语言分布、语言切换次数、国家分布。

**初始语言分布这一项，直接回答了要不要加第四种语言。** 不用再靠游客统计去猜。

## 本地调试

```bash
npx wrangler d1 execute sibisi --local --file=./schema.sql
```

```bash
npx wrangler dev --port 8787 --local
```

本地调试时把菜单的来源加进 `wrangler.toml` 的 `ORIGIN`（逗号分隔），比如 `http://127.0.0.1:8814`。`.dev.vars` 里放本地用的 `TOKEN`，这个文件不进 git。

## 免费额度够不够

Workers 每天 10 万请求，D1 每天 10 万行写入、5 GB 存储。

按每天 60 桌扫码估算：事件批量发送，**每天约 120 个请求、不到 200 行写入**，大约是额度的 0.1%。第 1 期加上菜品曝光之后约 3,600 行/天，还是 3.6%。生意翻十倍也在免费额度内。

## 已知的坑

- **收集口是公开的，挡不住有人拿 curl 直接灌数据。** Worker 会校验来源头（挡住别的网站的浏览器）、字段白名单和大小上限，但公开端点没有真正的办法杜绝伪造。小店的菜单，这个风险可以接受；真被灌了，数据能按时间段删掉重来。
- **只看得见扫码的人。** 没扫码、直接问服务员的客人完全不在数据里，而且扫码的人本身偏年轻、偏外国人。拿这份数据下「哪道菜最受欢迎」的结论，只对扫码客群成立。
- **样本小。** 一天几十桌，单项指标一周可能只有十几个数据点，别过度解读。
